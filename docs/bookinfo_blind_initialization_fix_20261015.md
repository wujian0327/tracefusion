# Bookinfo盲推断初始化修复与开发回归

2026年10月15日。先用合成检查修复初始化与上下文范围，再冻结代码并回放全部12份既有抓包。原始归档、旧版预测及旧统计均保留。没有新增采集，没有推进投稿。

## 修复内容

1. 盲推断只固定入口标签，取消全局兄弟服务顺序估计、根层批次线性分配及内部交换的固定初始归属。每条服务边独立选父，一个父操作可有零次、一次或多次同服务调用；后续轮次可修正。
2. 优先采用满足请求响应严格包含的候选；只有没有此类候选时才使用原有界容差/回退。请求容差50 ms、响应容差80 ms、兜底窗口250 ms、候选上限64沿用原值。跨主机时钟偏差或响应边界可能使正确父操作被严格候选排除，不能视为通用保证。
3. 累计业务上下文改取候选父操作的预测严格祖先，父自身由局部项计分，不引入兄弟与后代的令牌。预测祖先链出现环或标签不一致时取空。每轮归属或父键变化后重建缓存；扫描全部服务边以传播祖先变化。
4. 原有权重不变：局部20，完整配置祖先项40；关闭累计项为0，仅时间配置两项均0。历史的CONTEXT_MIX_WEIGHT=0.5仍随full配置记录，但根层批次分配已绕过，该系数不再参与新盲推断打分。最多20轮，记录实际轮数与是否收敛。
5. 历史非盲评路径保留兼容；新报告标记`independent-edges-ancestor-context-v2`。不读取真值顺序，不硬编码Bookinfo服务名或请求数。

## 剩余错误与解释边界

完整方法共29个内部RPC归属和父键错误，分布在6份运行，入口均正确识别。错误的真实入口与误选入口请求令牌集合相同，29对真实/预测父请求令牌集合也相同；其中23个子交换同时被两父区间包含，另6个真实父区间不满足严格包含。这是事后条件描述，不证明同值是充分原因；尚未审计这些6例的时间边界偏差来源。

本组数据已用于诊断旧实现，因此全部修复后结果属于开发回归。合成检查只验证预期行为，不构成性能证据。现有100种ID固定序列、短窗口和单一Bookinfo部署不足以证明对同值高并发、随机调用顺序、异步、递归或跨主机时钟误差的泛化。

## 当前主机与历史环境

用户于2026年10月15日提供当前实测：AMD Ryzen 9 9955HX，16核32逻辑线程；WSL2中的Ubuntu 24.04.3 LTS；内核6.18.54.1-microsoft-standard-WSL2；Docker客户端、服务端均29.1.3。Linux可见约23.47 GiB内存，不等于物理机内存。

当前Compose及历史源码快照中的Bookinfo Compose未配置CPU配额、CPU绑核或内存上限。原容器已不存在，无法docker inspect核实历史运行限制。当前版本尚未确认与9月20日实验一致，论文不可把当前值直接认定为历史环境。
